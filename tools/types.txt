# 寶可夢屬性（一隻一行：`內部名=屬性1,屬性2`，照圖鑑順序）
#
# 為什麼要有這個檔：上游的 COMPLETE_POKEDEX 萃取出來的欄位裡**沒有屬性**
# （dex 只有 n d no sp f ip sk b cs pe re ms i0 i30 i60）—— 整個上游 repo 都沒有。
# 和 tools/zh.txt 同一個性質：**repo 自己維護、上游沒有、重建時絕對不能弄丟。**
# 來源：Pokémon 本傳的屬性設定（主副屬性皆算）。只需要涵蓋這份快照的 246 隻。
#
# 誰在用：
#   達克萊伊「夢魘（能量填充M）」 —— 讓幫手隊伍中**惡屬性以外**的寶可夢活力下降 12
#   拉帝歐斯「流星群（樹果遽增）」 —— 隊伍中**不同種類的龍屬性**幫手越多，樹果越多
#   本週活動加成的三個屬性限定項（食材 +N 個／主技能發動率 +N%／主技能等級 +N）
#
# ⚠ 格式 2026-09-14 從 `## DARK` 分區改成一隻一行。理由是補滿 18 屬性之後，
#   分區格式要核對「某一隻對不對」得跨 18 個清單找，而漏掉一隻**完全沒有症狀**
#   （那隻只是永遠不符合任何屬性活動）。一隻一行照圖鑑順序，246 行可以直接掃。
#
# ⚠ 屬性名只能是這 18 個，而且**它們的內部名來自上游** `common/src/types/berry/berries.ts`
#   的 `Berry.type`（18 顆樹果剛好一顆一個屬性）：
#     normal fire water electric grass ice fighting poison ground
#     flying psychic bug rock ghost dragon dark steel fairy
#
# tools/extract-data.mjs 有四道守門，任何一道不過就 throw、不會產出壞掉的 game.json：
#   1. 名字必須在 dex 裡（打錯字不會有症狀，只會讓那隻靜靜地被漏掉）
#   2. **246 隻每一隻都必須至少有一個屬性**（漏一隻就是「永遠不符合任何活動」）
#   3. 屬性名必須是上面那 18 個
#   4. **交叉驗證**：每一隻的樹果（`berry.type`）所對應的屬性，必須出現在它這一行裡。
#      這是唯一有上游來源的一層 —— 目前 246/246 通過。擋不到的是雙屬性的**第二個**
#      屬性（樹果只反映單一屬性），那一層靠寶可夢箱的屬性標籤讓使用者核對。
#
# 之後若上游開始提供屬性欄位，就改成從那裡抓，並刪掉這個檔。
